## 章节标题的写法

固定格式 **`主题：一句判断`**。冒号左边是导航标签，右边是这一章的结论。

| 只有标签（不合格） | 带判断（合格） |
|---|---|
| GTM 策略 | GTM：90% 与 100% 是两个物种 |
| 护城河分析 | 护城河：被发现的，不是规划出来的 |
| 团队与流程 | 起源故事：一个月，一个山洞 |
| 产品迭代原则 | 迭代原则：colleague-pilled 的产品哲学 |
| 发布前的准备 | 发布前的 Unshipping：减少而非增加功能 |

h3 同理，但可以短一些，是一个可独立成立的小论点：「内部自己长出来的 chief of staff」「早期用户不只找品味领袖」「Cursor 为什么还在赢：从来不觉得自己赢了」。

## TL;DR 的锚点链接

TL;DR 每条都是一个判断，读者想深挖就得能跳到正文。做法：

1. 正文写完、文档已创建后，获取目标段落的 block id。
2. 拼 `<文档URL>#<block_id>`，把 TL;DR 里对应的那句话包成 `<a href="...">`。
3. 链接包的是**具体那一句**，不是整条 li。整条都变蓝反而没了重点。

8–12 条，每条结构是「加粗判断 + 三五句展开」。这是全篇信息密度最高的地方，别为了好看压缩成一行。

## 颜色和 emoji 的固定用法

| 用途 | 写法 |
|---|---|
| 顶部主要判断 | `<callout emoji="💡">` |
| 置信度框架 | `<callout emoji="💡">` |
| 章末置信度：高可信 | `<callout emoji="✅">` |
| 章末置信度：新信息且合理 | `<callout emoji="💡">` |
| 章末置信度：营销口径 | `<callout emoji="❗">` |
| 章节之间 | `<hr/>` |
| 原话引用 | `<blockquote>`，英文原文 + `——` + 中文 + `[HH:MM:SS]` |
| 阶段/时间线、并列对照 | `<table>` |

画板位置：总览图在 title 下方（配一行加粗引题），每章一张放在 h2 正下方，Summary 一张。

## 延伸翻译文档

结构简单得多：`<title>` → 卷首推荐语 callout（`💡`）→ 一段翻译说明（基于哪天抓取的版本、条目顺序与原文一致、来源链接保留）→ 正文。

推荐语要回答三个问题：谁在哪里推荐的、他的论点是什么、这东西和主文档是什么关系。例如：

> 这份清单来自 Stripe 联合创始人兼 CEO Patrick Collison 的个人网站。OpenAI 的 Tara Seshan 在 Lenny's Podcast 里专门推荐过它。她的论点是：AI 把执行的门槛打下来之后，真正稀缺的不再是能力，而是野心。而这份清单上的项目，全都发生在这些 AI 工具出现之前。
> 它讲的其实不是 AI，而是「人类高效协作」的范式……AI 改变的只是：这样的项目，理应多得多。

每个条目保留 `<em>来源：<a href="...">书名/文章名</a></em>`，一个链接都不能丢。

## 编辑既有文档的坑

用户的补充要求几乎都是**局部修改**，不要重新 overwrite 整篇——文档里已经有上传好的画板和图片，overwrite 会全部清掉。

- 用精确的 block 插入、替换、删除和字符串替换能力改，不要全量覆盖。
- block 替换通常会**换掉 block id**，旧 id 立即失效。链式操作要先重新获取新 id。TL;DR 里挂了锚点的段落被替换后，锚点要一起更新。
- 删列表后检查孤儿列表项是否漂进相邻章节。
- 移动块后重新读取文档，确认目标块没有静默丢失。
- 大批量插表/插图：先写含占位符的正文骨架，再逐个替换；切勿事后再全量覆盖。
- 新增或删除章节后，同步更新 TL;DR 和 Summary 里的 `〔对应第 N 节〕` 回指编号。
