# 翻译与语言优化规范

这套规范完整收录在 Skill 中。执行时不依赖作者的私人文档、特定工作区文件或额外 prompt，外部用户拿到 Skill 后也能复现同样的语言风格。

目标不是把稿子写得“像报告”，而是让每段话同时做到三件事：**先下判断、再给证据、最后守住边界。**

## 一、正文的基本单元：判断—证据—边界

一段只解决一个问题，推荐结构：

1. **第一句加粗，直接下判断。** 不从背景、过程或“近年来”写起。
2. **中间解释机制。** 写清楚为什么成立，因果链怎么运转。
3. **接具体证据。** 使用数字、产品动作、时间线、原话或外部材料。
4. **必要时收束边界。** 明说“公开材料尚未确认”“这是本文推测”“不足以证明……”。

示例：

> **真正的风险不在于产品形态落后，而在于学习速度落后。** 模型在真实长程任务中的失败模式，无法从内部 benchmark 与既有评测中充分暴露；一线对手已经通过产品承接真实任务，把失败转化为训练输入。如果没有自己的闭环，模型迭代将持续依赖公开评测与人工构造任务，而这些材料只代表“已被理解的问题”。

这段有效，是因为开头给判断，中间给机制，结尾没有喊口号，而是把风险落到“学习输入变薄”这件具体的事上。

## 二、章节标题必须包含判断

标题固定写成 **`主题：一句判断`**。冒号左边负责导航，右边负责给结论。

| 标签（不合格） | 判断（合格） |
|---|---|
| 模型竞争 | 模型竞争的胜负手，正在从纯研究转向研究与产品的闭环 |
| 数据飞轮 | 学习闭环一旦运转，其资产无法被速成 |
| 行业案例 | 一线公司的实践已经验证这条路径，竞争窗口正在关闭 |
| 组织建议 | 探索需要独立的组织形态，和不属于业务损益表的衡量方式 |
| GTM 策略 | GTM：90% 与 100% 是两个物种 |
| 护城河分析 | 护城河：被发现的，不是规划出来的 |

小节标题也写判断，但可以短一些，例如：“内部自己长出来的 chief of staff”“早期用户不只找品味领袖”“Cursor 为什么还在赢：从来不觉得自己赢了”。

写完标题后自检：没有读正文的人，光看标题能不能复述文章的论证路线？不能就继续改。

## 三、开头怎么写

开头不用“背景—现状—意义”三段式，直接给一张判断卡：

- 第一段：全文最重要的结论。
- 第二段：这条结论成立所需的机制或条件。
- 第三段：本文到底要论证什么，以及不打算论证什么。

例：

> **谁先建立端到端、更少人工干预的 AI 学习闭环，谁就在下一代模型竞争中拥有复利优势。**
>
> 学习闭环不会凭空运转：它需要一个围绕模型能力边界持续试错的探索空间，以及一套不按短期商业指标衡量的定位。
>
> **本文只论证一件事：为什么这种探索必须存在，以及它应当以什么方式存在。**

这种开头的好处是，读者在三段内就知道结论、条件和讨论边界。

## 四、把抽象观点写成因果链

不要只说“A 很重要”“B 能带来优势”。把中间环节列出来：

> 产品承接真实任务 → 暴露失败模式 → 转化为训练任务与运行环境 → 模型能力提升 → 更复杂的任务成为可能 → 产生新的学习机会。

如果一条判断写不出中间环节，它通常还只是观点，不是论证。

写因果链时注意：

- 每个箭头都要能回答“为什么”。
- 不要把相关性冒充因果。
- 机制没有证据时，用“可能”“有机会”“本文推测”，不要改成确定句。
- 把竞争优势落到可积累的资产上：任务分布、失败语料、运行环境、验收标准、用户纠正，而不是泛泛说“数据壁垒”。

## 五、精译不是直译

精译的目标，是把嘉宾真正想说的东西用中文讲清楚。

允许并鼓励：

- 把口语里绕回来的三句合成一句。
- 调整语序，先给判断，再讲过程。
- 补一句必要背景，让中文读者接得上。
- 为原文没有标题的一段提炼判断式小标题。

不允许：

- 加原文没有的论据。
- 把“我不确定，但可能……”改成肯定句。
- 为了通顺删掉转折、条件和保留意见。
- 把主持人的判断写成嘉宾的观点。

## 六、事实、转述、推断、建议要分层

读者要能一眼分开四层：

1. **原话**：blockquote，保留英文和时间戳。
2. **转述**：正文明确写“Roman 的判断是”“Lenny 补充说”。
3. **推断**：使用“我们推测”“这意味着”“〔推断〕”，并解释推断依据。
4. **建议**：写清建议对象和动作，不伪装成对谈结论。

好的边界句：

- “公开材料尚未确认这套环境已用于模型训练。”
- “这支持产品环境可以参与训练，不足以证明用户轨迹已经进入参数训练。”
- “将探索所得用于更新训练方向，是本文提出的进一步建议。”
- “现有证据支持竞争范围扩大，尚不足以证明整体进入边际收益递减阶段。”

坏的边界句：

- “可以看出，这必然会……”
- “毫无疑问，未来一定……”
- “行业已经形成共识……”（没有证据时）

## 七、引用格式

英文原文 + `——` + 中文翻译 + 方括号时间戳，放在 `<blockquote>` 里：

> “Truly throwing a no-look pass to a colleague and being like you got this. Here's the context. Go off and run.” —— 真正像给同事传一个不看人的传球：这事你能行，上下文在这儿，去跑吧。[01:03:05]

保留英文，是为了让读者核对翻译，也方便继续引用。

- 一节最多两三段引用，引用是证据，不是填充。
- 先讲清论点，再放引用支撑，不用引用开场。
- 自动字幕有明显错词时，不用那句做金句。
- 引用中的犹豫、限定词和语气强弱要保留。

## 八、术语与专名

- 人名、公司名、产品名保留英文：Roman Ugarte、Cursor、Grok Bot、OpenAI、Codex。
- 核心概念第一次出现写“英文（中文）”，之后选择更自然的写法：steering（掌舵）、rowing（划船）、unshipping、colleague-pilled、verifier。
- 内部黑话原样保留再解释：`shipping your org chart`、`Feel the AGI`、`Is this maximally accelerated?`。
- 数字和时间窗照抄，不随意约等于：`2–3 个月`、`82 分钟`、`200 到 300 人`、`70%`。
- 中英文之间留半角空格；中文句子用中文标点。

## 九、语气：克制，但不含糊

这套文风不是温吞。该下判断时下判断，该限定时限定。

- 用“长期领先优势，取决于能否……”而不是“……具有非常重要的意义”。
- 用“考核方式，决定探索的存亡”而不是“合理的考核方式有助于探索团队更好发展”。
- 用“具体产品可以退出，验证过的研究结论和实验环境要留下”而不是“需要做好相关沉淀”。

判断要强，证据要硬，边界要窄。不要为了显得谨慎，把每句话都写成“可能存在一定程度的影响”；也不要为了显得有气势，把推测写成事实。

## 十、去 AI 味：内置检查表

这份检查表是 Skill 的组成部分，不依赖外部 Humanizer 工具。

### 删空话

删除或改写：赋能、抓手、闭环（除非真在描述循环机制）、生态（抽象用法）、格局、维度（非数学）、综上所述、值得注意的是、不难发现、总的来说、在……的加持下、进一步地、具有重要意义。

### 控句式

- 破折号每千字不超过 2 个。
- “不是 X，而是 Y”全篇最多两三次。
- 避免“三连排比”撑气势。
- 避免段末用另一种说法重复段首判断。
- 避免每段都用“首先、其次、最后”。
- 不做“回顾—升华—展望”的标准三段式收尾。

### 控加粗

- 每段第一句可以整句加粗，用来承载判断。
- 段内只加粗真正影响理解的词组，不要半段都是粗体。
- 表格里的分类名、TL;DR 每条的判断可以加粗。

### 控证据

- 每个强判断附近必须有数字、案例、引语或来源。
- “行业共识”“一线公司都在做”必须列具体公司和动作。
- 外部证据与嘉宾自述分开写。
- 如果证据只支持可能性，就写“有机会”“值得关注”，不要写“证明”。

### 控结尾

结尾落到一个有限而明确的建议，不喊口号：

> 我们的建议有限而明确：保留独立的探索位置，并用学习速度而不是短期商业指标衡量它。具体形态和节奏，适合在方向确认后另行讨论。

## 十一、终检顺序

交付前按以下顺序扫，不要一遍混着改：

1. **只看标题**：能否复述全文论证路线？
2. **只看每段第一句**：是不是判断？有没有重复？
3. **只看证据**：每个强判断有没有支撑？
4. **只看边界词**：事实、推断和建议是否混淆？
5. **只看语言**：删空话、破折号、排比和机械加粗。
6. **朗读一遍**：句子是否太长，是否像人在说话。

如果当前环境提供 Humanizer 类能力，可以把它作为第七步辅助扫描；没有也不影响执行，这份规范本身已经完整。
